# 4일차 장면과 시스템 구조 체크리스트

[AGENTS.md](../AGENTS.md)의 외부 참고 자료에 있는 **팀프로젝트 4일차 장면과 시스템 구조.pdf**를 기준으로, 아래 순서대로 진행한다. 괄호 안의 숫자는 PDF 뷰어에서 표지를 1쪽으로 센 페이지 번호다. PDF의 로봇 A 예시는 문서 형식만 참고하고, 병 10개·3칸 선반·카메라 인식 등 예시 조건은 가져오지 않는다.

## 1. 장면을 만들기 전에 시험 조건 확정 (4쪽, 11–12쪽)

- [x] 장면 v0은 박스 위치를 고정해 기본 동작을 점검한다. 최종 시험은 병 시작 좌표와 B라인 컨베이어 벨트 위 박스 정지 위치를 사전에 짝지은 10쌍을 각 1회 시험한다. 박스는 회차 초기화 때만 옮긴다. [문제 정의서](problem.md)와 [요구사항 명세](requirements.md)에 반영했다. (4쪽, 11–12쪽)
- [x] 시연 범위는 마지막 병 1개의 병목 파지·이송·배치다. 병 시작 좌표와 목표 칸 좌표는 초기화에서 제어 코드로 전달하고, 영상 인식·빈 칸 탐색·벨트 구동·움직이는 박스 추적은 범위에 넣지 않는다. (11–12쪽)

## 2. D07 [장면 구성표](scene.md) 작성 (11–12쪽)

- [x] [팀 차터](charter_v2.md)의 로봇팔·그리퍼 후보, 제조사 모델 출처, 병목 파지 검증 기준을 장면 구성표에 적었다. (11–12쪽)
- [x] 후보 모델을 MuJoCo에서 로드하고 관절 위치를 직접 설정해 팔과 손가락의 자세가 바뀌는 것을 확인했다. 재현 명령과 확인 범위는 [장면 구성표](scene.md#모델-로드-및-자세-변화-확인)에 적었다. (11–12쪽)
- [x] 팔·그리퍼 구동과 손가락 관절 연동을 구성하고, 단일 병 파지·들기 시험을 실행해 [결과를 기록했다](scene.md#단일-병-파지들기-시험). 병은 들렸지만 뚜껑·어깨 접촉으로 불합격했다. (11–12쪽)
- [ ] 뚜껑·어깨·몸통에 닿지 않고 병목만 잡아 들어 올리는 시험을 통과한 뒤, 채택할 파일과 로봇 초기 자세를 확정한다. (11–12쪽)
- [x] 대상 병 1개, 기존 병 3개, 마지막 칸이 빈 2×2 박스, 정지한 B라인 컨베이어 벨트, 투입 구역의 구성과 가정값을 적었다. 길이는 m, 질량은 kg로 표기하고, 고정 요소와 회차별 변경 값을 구분했다. (11–12쪽, 15쪽)
- [ ] v0의 기준 박스 위치를 정하고, 벨트 적재 구간에서 박스 바닥 전체를 올려놓을 수 있는 범위와 구분해 적는다. 최종 시험 전에는 배치 가능 범위와 로봇 도달 범위를 확인해 병 시작 좌표와 박스 위치의 10쌍을 회차표로 확정한다. 10쌍의 수치 확정은 v0 제작의 선행 조건이 아니다. (11–12쪽)
- [x] 병목·보호 대상 몸통·병 바닥, 목표 칸 바닥·벽, 기존 병을 구분하는 이름과 경계를 정리했다. XML 검증 기대값으로 병 4개, 질량 합 0.600 kg, 3칸 점유·1칸 비움을 적었다. 실제 XML 검증은 3단계에서 진행한다. (12쪽, 15쪽)

## 3. MuJoCo 장면 v0 생성 및 검증 (15–16쪽)

장면 v0는 MuJoCo에서 처음 만드는 기본 작업 장면이다. 로봇팔·그리퍼, 집을 병 1개, 기존 병 3개와 마지막 빈 칸이 있는 2×2 박스를 배치하고 박스는 정지한 B라인 컨베이어 벨트 위 한 위치에 고정한다. 먼저 뷰어에서 물체가 겹치지 않고 마지막 칸이 비어 있는지 확인한다. 제어 코드가 준비되면 같은 장면에서 병목을 잡아 빈 칸에 넣는 기본 동작을 점검한다. 박스 위치를 바꾸는 최종 10회 시험과는 별개다. (4쪽, 15–16쪽)

- [ ] 구성표를 바탕으로 `scenes/`에 MJCF XML을 만든다. 에이전트에 맡길 경우 기반 모델, 장면 구성표, 객체 이름·단위, 완료 기준을 함께 전달한다. (15쪽)
- [ ] 확인 코드로 XML이 로드되는지 검사하고, 병 개수·질량 합과 초기 배치가 구성표의 기대값과 일치하는지 확인한다. 실행 명령과 실제 출력을 저장한다. (15–16쪽)
- [ ] 뷰어에서 초기 자세를 확인하고 시뮬레이션을 몇 스텝 진행한다. 병·박스·그리퍼가 겹쳐 튀지 않는지와 목표 칸이 비어 있는지 확인한다. 문제가 있으면 XML을 수정하고 수치 검사까지 다시 한 뒤, 통과한 장면의 스크린샷을 저장한다. (4쪽, 16쪽)

## 4. D06 시스템 구조 작성 — `docs/architecture.md` (5–6쪽, 8쪽)

- [ ] 모듈 관계도를 그린다. 초기화에서 병·목표 칸 좌표를 넘기고, 상태 기계가 접근 → 파지 → 이송 → 배치 → 후퇴·대기 복귀를 지시하는 흐름을 표시한다. MuJoCo 관측값이 상태 기계와 판정·로그로 어떻게 돌아오는지도 표시한다. (5쪽, 8쪽)
- [ ] 관계도의 각 화살표를 인터페이스 표로 옮긴다. 송신·수신 모듈, 데이터 이름·형식, 좌표계·단위, 전달 시점(초기화·제어 주기·회차 종료 등)을 적는다. 병·목표 칸 좌표, 손끝 목표와 그리퍼 명령, 접촉·위치·시간 관측을 포함한다. (6쪽, 8쪽)
- [ ] MuJoCo 관측으로 [기존 판정 코드](../src/judge.py)의 `TrialResult`를 채우는 방법을 정한다. 인쇄면 접촉·낙하·기존 병 접촉·박스 벽 접촉을 구분하고, 배치 후 1초 동안의 바닥 지지와 칸 경계로 안착을 판단한다. 사이클타임 측정 시작·종료 이벤트도 적되, 목표 상한은 D03대로 예비 시험 후 본시험 전에 확정한다. (5–6쪽, 8쪽)

## 5. D08 안전 개념 작성 — `docs/architecture.md` (7–8쪽)

- [ ] ‘금지 상황 → 감지 방법 → 예방·발생 시 동작’ 표를 만든다. 최소한 인쇄면 접촉, 이송 중 낙하, 기존 병 접촉을 다루고, 감지한 회차를 어떻게 실패로 기록하고 종료할지 정한다. 자동 재시도나 실패 복구는 추가하지 않는다. (7–8쪽)
- [ ] 안전 개념을 이 저장소의 요구사항 ID에 연결한다. PDF 예시의 R-05를 그대로 쓰지 않는다. 이 프로젝트에서 안전 요구사항은 R-04(기존 병 접촉), R-05는 사이클타임이다. 박스 벽 접촉(R-06)은 별도 기록 항목으로 구분한다. (7–8쪽)
